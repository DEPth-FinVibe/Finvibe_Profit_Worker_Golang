## 배경

가격 이벤트 경로는 `price-event-reconciliation` 작업으로 원자적 평가액 교체, 최신성 보호, 가격 DLT 복구를 갖췄다. 반면 Kafka 에러 처리와 매매·포트폴리오 캐시 갱신에는 다음 공백이 남아 있다.

## 확인된 기존 동작

- handler가 에러를 돌려주면 배치를 되감고 **대기 없이** 다음 poll에서 다시 처리한다. 재시도에 한도가 없다.
- decode 실패도 같은 경로를 탄다. 깨진 메시지 하나가 해당 파티션을 **영구 정지**시킨다.
- 매매·포트폴리오 이벤트에는 DLT가 없다.
- 매매 1건은 Redis 명령 약 7개로 따로 반영되고, 처리 완료 마커(`processed:trade:<id>`)는 맨 끝에 기록된다. 중간에 실패하면 재시도에서 앞 명령이 다시 반영된다.
- 특히 `pf:<id>`의 `cvp`와 `scv:<stockId>`가 별도 명령이라, 사이에서 끊기면 둘이 영구히 어긋난다. 가격 경로는 `scv`를 기준으로 delta를 계산하므로 이 불일치가 계속 남는다.
- 수량은 GET 후 SET으로 갱신한다.
- 포트폴리오 생성·삭제도 여러 단계가 원자적이지 않고, 이벤트 단위 중복 방지가 없다.
- Go 워커에는 Kafka producer가 없다.

## 해결할 문제

1. 깨진 메시지가 파티션을 멈추지 않아야 한다.
2. 일시 장애에서는 간격을 두고 한도 안에서 재시도해야 한다.
3. 재시도를 포기한 매매·포트폴리오 이벤트를 잃지 않아야 한다.
4. 매매·포트폴리오 이벤트를 몇 번 다시 처리해도 캐시에 한 번만 반영돼야 한다.

## 목표

- 가격: 깨진 메시지와 재시도를 포기한 배치는 버리고 지표로 남긴다.
- 매매·포트폴리오: 깨진 메시지와 재시도를 포기한 레코드는 `<topic>.DLT`로 보낸다.
- 매매·포트폴리오 캐시 쓰기를 해시 단위 Lua와 마커로 원자적·멱등하게 만든다.

## 변경 범위

- Kafka consumer의 에러 분류, 재시도, DLT 발행
- DLT producer와 DLT 토픽 생성
- 매매·포트폴리오 캐시 쓰기의 Redis 원자화
- 관련 지표, 테스트, 작업 문서

## 제외 범위

- 가격 경로의 평가액 계산 방식 변경 (이미 원자화됨)
- Backend Monolith, Batch, Manifest 저장소 변경
- Redis 키 배치 변경
- 매니페스트 배포

## 완료 조건

- 깨진 메시지가 있어도 앞뒤 레코드가 처리된다.
- 매매·포트폴리오 레코드가 5분 재시도 후 DLT로 가고, 뒤 레코드 처리가 이어진다.
- 재시도 대기 중에도 컨슈머가 그룹에서 빠지지 않는다.
- 매매 이벤트 처리 중간에 실패한 뒤 재시도해도 수량·평가액·구매액이 한 번만 반영된다.
- `cvp`와 `scv`가 항상 함께 바뀐다.
- `go test ./...`, `go test -race ./...`, `go vet ./...`가 통과한다.

## 위험과 제약

- 매매 재시도가 5분을 넘겨 DLT로 가면 같은 포트폴리오의 뒤 이벤트가 먼저 반영된다. DLT 재발행과 Batch reconciliation으로 보정한다.
- 마커 TTL(7일)이 지난 뒤 재처리하면 중복 검사가 되지 않는다.
- 가격 배치는 종목 락 경합도 재시도 대상이다. 경합이 길면 틱을 버리고 다음 틱이 복구한다.
- 실제 Kafka 브로커 대신 가짜 consumer로 재시도·pause 동작을 검증한다.
