## 문서 정보

- 작성일: 2026-09-22
- 기준 문서: `01-overview.md`, `02-plan.md`
- 상태: 결정 완료
- 리뷰 상태: 리뷰 필요

모든 결정은 사용자가 선택지를 보고 골랐다.

## D1. 깨진 메시지 처리

### 검토한 선택지

1. 가격은 drop, 매매·포트폴리오는 DLT
2. 모든 토픽을 별도 격리 토픽(`<topic>.invalid`)으로
3. 모든 토픽 drop

### 결정

- 사용자 선택: **1번**
- decode·필수값 검증 실패는 재시도하지 않는다.
- 가격은 로그와 `invalid_payload` skip 지표만 남기고 버린다.
- 매매·포트폴리오는 `<topic>.DLT`로 보낸다.

### 근거

- 가격 DLT(`market.stock-price-updated.v1.DLT`)는 이 워커가 복구용으로 소비한다. 깨진 가격 메시지를 넣으면 DLT consumer가 다시 실패하는 순환이 생긴다.
- 가격은 다음 틱이 최신값을 다시 싣고 온다.

## D2. 일시 장애 재시도

### 검토한 선택지

1. Java 워커와 동일: 가격 200ms × 2회 후 drop, 매매·포트폴리오 1s부터 2배·최대 30s 간격·총 5분 후 DLT
2. 무한 재시도 + backoff
3. 가격은 포기, 나머지는 무한

### 결정

- 사용자 선택: **1번**

### 트레이드오프

- 가격 배치는 종목 락 경합도 재시도한다. 경합이 400ms를 넘기면 틱을 버린다.
- 매매 재시도가 5분을 넘기면 같은 포트폴리오 이벤트 순서가 뒤바뀔 수 있다.

## D3. 재시도 소진 시 DLT 범위

### 검토한 선택지

1. 실패한 레코드만
2. 실패 레코드부터 배치 끝까지
3. 배치 전체

### 결정

- 사용자 선택: **1번**
- 매매·포트폴리오는 레코드 단위로 처리한다. 실패한 레코드를 5분 재시도하고, 소진되면 그 레코드만 DLT로 보낸 뒤 다음 레코드로 넘어간다.
- 재시도 대기에 들어가기 전에 앞 레코드의 offset을 커밋한다.

### 트레이드오프

- 장애가 길면 뒤 레코드도 각각 5분씩 재시도한 뒤 DLT로 가서, 처리가 매우 느려진다.

## D4. 재시도 대기 중 max.poll.interval.ms 준수

### 검토한 선택지

1. 할당된 파티션을 pause하고 Poll을 계속 호출
2. `max.poll.interval.ms`를 10분으로 올리고 sleep

### 결정

- 사용자 선택: **1번**
- 대기 중 새로 할당된 파티션도 pause한다. Poll이 메시지를 돌려주면 그 offset으로 seek해 잃지 않는다.
- 대기 중 레코드의 파티션이 회수되면 재시도를 멈추고, 새 소유자가 커밋된 offset부터 다시 읽는다.

## D5. DLT 토픽 생성 주체

### 검토한 선택지

1. Go 워커가 기동 시 AdminClient로 생성
2. 매니페스트·운영에서 생성
3. 브로커 자동 생성에 맡김

### 결정

- 사용자 선택: **1번**
- 매매·포트폴리오 DLT 토픽을 없으면 만든다. 파티션 1개, 복제 수는 브로커 기본값이다(Java 워커와 같음).
- 생성에 실패해도 기동은 계속한다. DLT 발행이 실패하면 그 레코드는 재시도 루프에 남는다.

## D6. 매매·포트폴리오 쓰기 원자화

### 검토한 선택지

1. `pf`·`usr` 해시 단위 Lua + 마커 키, 수량은 compare-and-set
2. 수량도 `pf` 해시로 옮겨 포트폴리오 쪽을 Lua 하나로
3. `cvp`·`scv`만 묶기

### 결정

- 사용자 선택: **1번** (포트폴리오 생성·삭제도 같은 방식)
- 쓰기마다 "마커 확인 → 반영 → 마커 기록"을 Lua 하나로 실행한다.
- 마커 키는 `applied:{<데이터 키>}:<이벤트 키>`다. 괄호 안 문자열이 데이터 키 전체라서, Redis Cluster에서 데이터 키와 항상 같은 slot이다.
- 매매 1건 = 수량 compare-and-set + `pf` 해시 Lua(`pv`·`cvp`·`scv`·`ac`) + `usr` 해시 Lua(`pv`·`cvp`).
- 보유 인덱스와 호환 projection(`portfolio:<p>:stock:<s>:current-value`)은 반영 후 상태를 기준으로 맞춘다.
- 마커 TTL은 7일이다.

### 근거

- 키 배치를 그대로 둬서 Batch·Monolith 변경과 데이터 이전이 없다.
- Java 워커에서 같은 방식을 실제 Redis로 검증했다.
